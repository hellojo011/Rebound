# Rebound

REFLEC BEAT 스타일의 안드로이드 리듬게임입니다. 같은 규칙으로 동작하는 독자 엔진이며,
채보는 평범한 텍스트 파일로 읽습니다.

## 플레이 방식

필드는 두 개의 바로 나뉩니다 — 아래는 내 바, 위는 상대의 바. 오브젝트는 내려와서 내
바를 지나가고, **지나가는 그 자리**를 쳐야 합니다. 레인은 없습니다. 타이밍만큼 위치가
중요하며, 고정된 위치는 원형 탭 포인트 세 개뿐입니다.

| 오브젝트 | |
|---|---|
| **탭** | 바를 지날 때 칩니다. |
| **골드** | 똑같이 치면 상대편으로 넘어갑니다. 손을 떼는 대신 **튕기면**(슬라이드) JUST REFLEC 게이지 한 칸을 소비해 강화된 탄이 되어 벽을 튕기며 날아갑니다. 아래로 튕기면 바닥을 차고 올라갑니다. 게이지가 비어 있으면 튕겨도 소비되지 않고 그냥 넘어갑니다. |
| **롱** | 머리부터 꼬리까지 잡고 있습니다. 유지하는 동안 KEEP이 쌓입니다. |
| **그린** | 바가 아니라 탭 포인트 위에서 판정됩니다. |
| **체인** | 한 자리를 공유하며 이어져 오는 연타입니다.|

오브젝트의 색은 소유자가 아니라 **진행 방향**을 나타냅니다. 나에게 내려오는 것은 따뜻한
색, 멀어지는 것은 차가운 색입니다. 필드를 공유하는 게임에서 한눈에 답해야 할 질문은
"이게 나한테 오는 거냐" 하나뿐이기 때문입니다.

판정은 **JUST → GREAT → GOOD → MISS** 순이며 각각 6 / 4 / 2 / 0점입니다. 롱을 유지하면
**KEEP**이 8분음표마다 1점씩 들어오므로, 같은 길이의 홀드는 어떤 템포로 쓰여도 같은
값을 받습니다. 게이지를 채우는 것은 JUST뿐이라 리플렉은 정확도에 걸려 있고, 성공하면
10점이 추가됩니다.

**클리어 게이지**는 오브젝트를 처리할수록 차오릅니다 — JUST·GREAT는 가득, GOOD은 절반,
MISS는 0. 만점 플레이가 정확히 100%에 닿고, 70% 이상이면 클리어입니다.

**일시정지**는 필드 중앙에서 두 손가락을 모으거나 뒤로 버튼을 누르면 됩니다. RESUME /
RESTART / QUIT 중에서 고릅니다. 재개할 때는 멈춘 지점 직전부터 카운트인이 다시
돌아가고, 앱을 벗어나면 혼자 진행되는 대신 메뉴로 돌아옵니다.

## 2인 플레이

대전은 항상 양쪽이 같은 채보를 미러링해서 칩니다. 모드가 정하는 것은 **먼 쪽을 누가
움직이느냐**뿐입니다.

- **1인** — 위쪽 절반을 CPU가 칩니다. 타이밍 오차와 흘리는 오브젝트를 각 오브젝트에서
  해시로 뽑기 때문에, 같은 채보를 같은 난이도로 돌리면 항상 같은 결과가 나옵니다.
  매번 주사위를 새로 굴리면 엔진을 고쳤을 때 결과가 달라진 이유가 코드인지 운인지
  구분할 수 없습니다.
- **2인** — 태블릿을 둘 사이에 눕힙니다. 위쪽 절반은 마주 앉은 사람의 것이고, 그 필드는
  내 필드를 반 바퀴 돌린 것입니다. 두 축이 모두 뒤집히므로 상대의 왼쪽이 내 오른쪽입니다.
  판정과 결과가 각자의 방향으로 따로 표시됩니다. 클리어 게이지는 없고 점수가 높은 쪽이
  이깁니다.

골드를 쳐도 상대편에 오브젝트가 생기지는 않습니다. **상대의 다음 오브젝트가 자기 경로
대신 그 탄을 타고 도착**할 뿐입니다. 오브젝트 하나가 다른 방식으로 등장하는 것이므로,
비행 시간은 두 지점 사이의 간격을 정확히 채우도록 늘거나 줄어듭니다.

## 곡

기본 데모는 assets 안에 있습니다. 나머지는 직접 넣는 `.reb` 파일이며, 다음 경로에
풀립니다.

```
Android/data/com.digiwb.rebound/files/songs/<song-id>/
```

외부 저장소이면서 앱 전용이라, 파일 관리자로 곡을 넣고 뺄 수 있고 저장소 권한이 필요
없으며 앱을 지우면 같이 정리됩니다. 곡 목록에서 가져오거나, 파일 관리자에서 `.reb`를
그냥 열어도 됩니다.

### `.reb` 패키지

곡 하나와 그 곡의 모든 난이도를 담은 zip입니다. 음원과 채보가 서로 떨어질 수 없게
하기 위한 구조입니다.

```
song.reb
├── rebound.manifest    곡 정보와 각 항목이 무엇인지
├── audio.mp3|ogg|wav   작성된 그대로의 인코딩
├── normal.rbc
└── hard.rbc
```

```
format=1
title=Example
artist=Someone
audio=audio.ogg
chart=normal.rbc
chart=hard.rbc
```

곡 단위 정보는 채보가 아니라 매니페스트에 둡니다. 한 곡에 채보가 여럿인데 제목을 두고
서로 다른 말을 하면 안 되기 때문입니다. 템포·레벨·오브젝트는 각 `.rbc`에 남습니다.


## 채보 형식 (`.rbc`)

```
title=Rebound Demo
artist=Rebound
audio=demo.wav
bpm=150
offset=0
columns=16
level=3
difficulty=NORMAL
end=24000
--
0001000000000000
0000000000000000
0001000000000000
0000000000000000
--
```

첫 `--` 전까지가 메타데이터입니다. 그 뒤로 `--`로 끝나는 블록 하나가 4박 한 마디이며,
행 수만큼 균등하게 쪼개집니다. 4행이면 4분음표, 16행이면 16분음표입니다.

| 문자 | |
|---|---|
| `0` | 없음 |
| `1` | 탭 |
| `2` | 골드 |
| `3` | 롱 시작 |
| `4` | 롱 끝 |
| `5` | 그린 |
| `6` | 체인 링크 |

**열은 거의 아무것도 결정하지 않습니다.** 바에 닿는 오브젝트는 랜덤한 위치에 떨어지며,
그게 이 게임의 방식이기 때문입니다. 열이 정하는 것은 그린이 어느 탭 포인트로 오는지와,
같은 순간에 쓰인 것들이 서로 다른 오브젝트라는 사실뿐입니다. 동시에 도착하는 것들은
바 위에서도 서로 떨어뜨립니다 — 같은 자리에 겹치면 아무리 잘 읽어도 따로 칠 수 없기
때문입니다.

한 열에 가깝게 이어 쓴 체인 링크는 하나의 연타가 됩니다. 착지 지점**과 접근 경로**를
함께 공유하므로 한 줄로 이어져 도착합니다.

마디 안에 `bpm=`을 한 줄 쓰면 그 행부터 템포가 바뀝니다. `end=`는 마지막 오브젝트 이후
까지 곡을 유지합니다 — 아웃트로가 있는 곡을 위한 것입니다. `#`는 주석, `//`는 행 끝
주석입니다.

## 에디터

곡 목록에서 edit을 탭하거나 상단의 Editor 메뉴로 들어갑니다. 

mp3·wav·ogg를 가져오거나(내장 데모 트랙으로 시작해도 됩니다) 마디선이 트랜지언트에
얹힐 때까지 템포와 오프셋을 맞춘 뒤, 파형과 같은 시간축을 공유하는 그리드에 오브젝트를
놓습니다. 탭 포인트마다 레인 하나, 바 오브젝트용으로 서로 교환 가능한 슬롯 몇 개가
있고, 종류는 툴이 정합니다.

- **TICKS** — 재생헤드가 오브젝트를 지날 때마다 히트음을 냅니다. 배치가 박자에서 살짝
  어긋난 것을 알아채는 가장 빠른 방법입니다.
- **PLAYTEST** — 실제 `.reb`를 만들어 패킹하고 실행합니다. 테스트 한 번이 작성기·
  아카이브·라이브러리를 모두 거칩니다.
- **SAVE**는 라이브러리에 넣고, **EXPORT**는 원하는 위치에 `.reb`를 씁니다.
- 저장은 곡을 교체하는 것이 아니라 **곡에 난이도를 더하는** 동작입니다.
  - 다만, 같은 메타데이터를 작성하여 저장하는 경우 해당 데이터를 덮어씌웁니다. 

기록되는 파일의 해상도는 채보를 따라갑니다 — 모든 오브젝트를 정확히 담을 수 있는 가장
성긴 분할을 고릅니다. 4분음표만 쓴 채보는 마디당 4행이 되고, 셋잇단은 가장 가까운
16분음표로 뭉개지는 대신 3분할로 기록됩니다.

## 설정

**오디오 싱크**(판정이 계속 LATE로 뜨면 올립니다), **스크롤 속도**, **오브젝트 크기**,
**스킨**이 있습니다. 판정 색은 일부러 스킨에서 제외했습니다 — JUST가 청록, MISS가
적색인 것은 장식이 아니라 정보이기 때문입니다.

설정은 곡 시작 시 한 번 읽고 그 판이 끝날 때까지 유지합니다. 곡 도중에 싱크나 크기가
바뀌면 아직 기록 중인 점수의 기준이 흔들립니다.

## 빌드

Android SDK와 기기(또는 에뮬레이터)가 필요합니다.

```bash
./gradlew :app:installDebug
```

엔진 테스트는 순수 JVM 테스트라 1초쯤 걸립니다.

```bash
./gradlew :core:test
```

데모를 오토플레이로 바로 실행합니다. 채보를 완벽하게 처리하므로 타이밍과 화면을 확인
하기에 가장 빠릅니다.

```bash
adb shell am start -n com.digiwb.rebound/dev.rebound.MainActivity --ez autoplay true
```


## 구조

```
core/    순수 Kotlin, 안드로이드 의존성 없음. 채보 모델·파서·작성기, 필드 좌표,
         타이밍, 판정, 점수, JUST REFLEC 게이지, 탄 경로, CPU, .reb 형식.
         테스트가 있는 곳입니다.

app/     안드로이드 앱.
  cpp/     Oboe 오디오 엔진과 JNI 브리지.
  audio/   PCM 디코딩·리샘플링, 곡 클럭.
  song/    설치된 곡 라이브러리.
  render/  도형 셰이더, 스킨, 필드 지오메트리.
  game/    렌더러, 입력, HUD.
  editor/  타임라인, 파형, 오브젝트 그리드.

tools/   데모 트랙과 런처 아이콘 생성기.
```


## 라이선스

여기 있는 코드는 전부 독자적으로 작성한 것입니다. REFLEC BEAT는 코나미의 것이며, 이
프로젝트는 코나미와 아무 관련이 없고 후원받지 않았으며, 원작의 어떤 자산도 포함하지
않습니다.
